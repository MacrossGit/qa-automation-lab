# UI E2E-тесты Onliner

Простой учебный набор UI-тестов для `https://catalog.onliner.by/` на Java, Selenium и JUnit 5.

Проверяемые сценарии:

- поиск товара;
- смена города доставки;
- добавление товара в корзину и удаление из неё;
- вход в существующую учётную запись — только при передаче секретов через окружение.

Для демонстрации есть `CatalogDemoE2ETest`: один браузер посещает все основные
разделы, прокручивает страницы, ищет десять товаров и очищает корзину в `finally`.

Также есть быстрые модульные тесты без Selenium:

- `TestRunSettingsTest` проверяет режим видимого/headless-браузера;
- `TestAccountTest` проверяет правило запуска авторизационного теста.

Тесты не нажимают «Оформить заказ» и не запускают оплату.

## Запуск

Нужны JDK 25+, Maven и Google Chrome.

```powershell
mvn test
```

Только модульные тесты:

```powershell
mvn test "-Dtest=TestRunSettingsTest,TestAccountTest"
```

Чтобы не открывать окно браузера:

```powershell
mvn test -Dheadless=true
```

Для наглядной демонстрации длинного сценария в одном окне Chrome:

```powershell
mvn test "-Dtest=CatalogDemoE2ETest" -Dheadless=false
```

Во время демонстрации в консоль выводятся сообщения `[DEMO]` о текущем действии,
а между действиями добавлены короткие паузы.

Демонстрационный сценарий входит в учётную запись после обхода каталогов. Перед
его запуском заполните `.env` в корне проекта. Файл уже исключён из Git.
Если Onliner покажет CAPTCHA, демонстрация выведет сообщение и сразу вернётся
в каталог, чтобы продолжить поиск и работу с корзиной.

Для теста авторизации заполните `.env` в корне проекта. Создайте его копированием
`.env.example`; этот файл содержит только названия переменных и может храниться в Git.

При запуске в CI переменные окружения имеют приоритет над `.env`.

```powershell
Copy-Item .env.example .env
# Заполните ONLINER_EMAIL и ONLINER_PASSWORD в файле .env
mvn test
```

Без этих двух значений тест авторизации будет отмечен как пропущенный, остальные тесты выполнятся.
